# ChatGPT Work 课后处理流程（V1）

本文件位于 `C:\codex\AI家庭学习\data\rules\WORKFLOW.md`。`C:\codex\AI家庭学习` 是“小孩学习”的唯一项目入口，本文件所在的 `data` 是“小芽家庭学习”软件的唯一运行数据目录。为兼容历史文件，协议名继续使用 V1；当前正式支持 `hanzi`（汉字）、`english_letter`（英语字母）与 `math`（数学启蒙），不得添加英语单词、拼音课程或其他未定义学科。

## 收到“处理最新学习记录”后

1. 读取 `rules/PROTOCOL_V1.md` 与 `schemas/` 中三个输入输出协议。
2. 读取 `state/learning-state.json`，它是软件当前正式状态；不要直接修改。
3. 按文件名时间顺序读取 `raw/sessions/*.json`，找到 `state.appliedSessionIds` 尚未覆盖的最新记录，并读取当前 `ai/next-lesson.json` 核对这次课程原计划的新学与预习编号。`raw/` 只读，严禁修改、重命名或删除。手机端上传到云端的记录由电脑端 `app-mobile/scripts/cloud-agent.mjs --pull-records` 以只追加方式归档到 `raw/sessions`（同名文件绝不覆盖，写入前做结构与上传摘要双重校验；摘要复现失败会如实标注）；归档后按前述顺序继续处理。
4. 仅根据原始事件分析独立答对、提示后答对、两次错误、示范、反应时间与题型；不要把“展示过”写成“已经会”。
   - 如果确认某些历史题目在可见题干中泄露了正确答案，把对应原始事件的 `eventId` 写入 `state-update.json.ignoredEventIds`。原始记录仍不得修改；软件会持久排除这些无效证据，且这些事件不得支持升级或“稳定掌握”。
5. 覆盖生成以下三个文件：
   - `ai/state-update.json`
   - `ai/next-lesson.json`
   - `ai/parent-report.md`
6. 生成后自行按 `schemas/` 检查字段、枚举、数量和引用；不要直接改 `state/learning-state.json`。
7. 从唯一源码仓库 `https://github.com/YU-xiaolin/xiaoya` 临时取得指定提交，在临时源码的 `app-source/` 运行 `npm run voice-pack`，再运行 `npm run voice-pack:audit`；两步都必须显式设置 `FAMILY_LEARNING_DATA_DIR=C:\codex\AI家庭学习\data`，并使用仓库内 `.codebuddy/tools/edge_tts_voice.py`。为当前课程、巩固练习、预习和已学内容测试生成晓伊自然语音，确认所有运行时朗读文本都有非空 MP3；完成后清理临时源码，不恢复本地长期源码副本。若生成或覆盖检查失败，不得用 Windows 系统机械音冒充完成，须明确告诉家长语音包尚未更新成功。

## 状态更新硬边界

- 汉字状态：`未学 → 初见 → 学习中/薄弱 → 会认 → 稳定掌握`。
- 字母状态：`未学 → 初见 → 能指认/薄弱 → 能说出 → 稳定掌握`。
- 数学状态：`未学 → 初见 → 学习中/薄弱 → 理解 → 稳定掌握`。
- 单次更新不得跨级升级。
- 需要提示才答对仍是薄弱证据。
- “稳定掌握”必须由软件从全部 raw 记录复核：至少 3 个不同 session 中独立答对，并覆盖至少 2 种 questionType。AI 提议不满足时软件会拒绝。
- `basedOnSessionIds` 必须列出本次分析实际读取并作为依据的 sessionId。
- `targetRef` 必须来自 `learning-state.json`；不要自己发明编号。

## 下一课硬边界

- 正常汉字学习日安排 6 个不同的新汉字。轻松预习不是预习今日新字，而是显示下一次课程计划新学 6 个汉字中的前 4 个。只有最新 raw 证据明确显示孩子疲劳、连续薄弱或多次由家长提前停止时，才可减少新字或只复习，并必须在 `teacherNote` 与家长报告中说明原因。英语字母每日新学仍不得超过 6 个。
- 汉字与字母混合出现在同一课时，仍须遵守单课最多 20 个核心任务。正常情况下同时保留 6 个新汉字和最需要的到期复习；若到期项很多，先挑最紧急的复习项，不要仅因待复习总量大就把新汉字降为 0。
- 数学课程不写入 `next-lesson.json`，由软件依据所选阶段、正式状态和 `catalog/数学启蒙课程.json` 自动生成。按家长 2026-09-07 的明确要求，六个阶段全部开放，可直接选课；0.2.5 首次默认选择 10 以内加减，此后记住所选阶段。每次数学课最多 4 个新目标；运算课先安排数量与分合热身，再看图理解和练算式。课程开放与掌握状态分开，不得为了解锁而提高正式状态。
- 顺序：到期薄弱/不会 → 少量旧内容 → 新内容。
- 一题只做一个核心任务。
- V1 只允许 `recognition` 和 `choice` 两种题型；选择题必须恰好 4 个选项。
- 选择题的可见 `prompt` 严禁直接出现 `correctAnswer`（英文字母按大小写不敏感比较），避免孩子照着题干匹配答案。汉字选择题用带声调拼音作可见线索；英语字母选择题用不显示字母的听音提示。若需要保证系统朗读准确答案，可把含答案的朗读文案放在 `speechPrompt`，软件只朗读、不显示。拼音在这里只是测试线索，不扩展为拼音课程。
- `prompt`、`speechPrompt`、`context`、`hint`、`demonstration` 和 `reinforcement` 都会出现在孩子的课堂中，必须直接对孩子表达，例如“请说出屏幕上的数字”“请读出屏幕上的汉字”；不得写“请孩子……”“孩子自己……”“家长先……”等旁观或对家长发号施令的口吻。家长操作说明只能放在家长管理页、`teacherNote` 或家长报告中。
- 新内容优先选正式状态中最靠前的 `未学` 条目。
- `metadata.previousNewHanziRefs` 必须记录上一次“今日课程”原计划新学的汉字编号，正常完成时为 6 项；优先取最新 raw 中 `activityMode=lesson` 的 `plannedNewHanziRefs`。软件的“巩固练习”只练这组上次新字，不得改成本课普通复习项或今日新字。
- `metadata.nextPreviewHanziRefs` 必须记录下一次课程计划新学 6 个汉字中的前 4 个。生成下一课时，最新 raw 的 `plannedNextPreviewHanziRefs` 必须成为本课 6 个新汉字的前 4 个，再按正式课程顺序补后 2 个；随后再为更下一课计算新的 4 个预习编号。
- 刚完成课程的 `plannedNewHanziRefs` 即使在当前正式 state 中仍显示“未学”，生成下一课时也必须排除，不能再次当作新字。
- 软件的“全部内容”测试必须覆盖正式状态中本学科全部非“未学”项目；测试不按 20 题分轮，所选题目在同一个 session 中连续完成。正常学习课程仍最多 20 个核心任务。
- 第一次答错先提示，第二次才示范，软件会自动安排至少隔 3 题复测；课程 JSON 不需要自行复制复测题。
- 数学一次只考一个核心概念，优先使用数字、实物数量、比较图和简单算式；不要求书写，不得跳过数感、数量对应和分与合直接训练机械计算。
- 不得加入 `english_word`、英语拼写、拼音课程或其他未定义学科。

## parent-report.md 模板

用简短中文写：日期/时长；本次学科；复习；新学；独立答对；薄弱/不会；孩子状态；下次建议；建议状态变化。数学记录要说明当前阶段、数字与数量是否真正对应、是否依赖数数或提示。不得声称软件尚未通过的状态已经正式生效。

完成后告诉家长：“已经生成并校验所需文件，请回到小芽家庭学习，点击‘检查 AI 新内容’。”
